# Contributing

Thanks for helping build prompts people can trust and adapt.

## Before proposing a prompt

1. Search the repository for the outcome, not only the title.
2. Use the [Prompt Canvas](templates/prompt-canvas.md).
3. Test with at least one current general-purpose model.
4. Remove secrets, personal data, proprietary inputs, and unverifiable claims.
5. Confirm the prompt is original. If it adapts compatible material, list the source, author, license, and exact changes.

Do not submit scraped prompt collections, lightly paraphrased commercial content, jailbreaks, deceptive automation, or content you do not have permission to license.

## Quality bar

A useful contribution has:

- a concrete user outcome and clear placeholders;
- only the context necessary for that outcome;
- evidence rules that prevent invented facts;
- a bounded, inspectable output format;
- a meaningful human check;
- extra caution for decisions affecting rights, money, health, safety, employment, security, accessibility, or compliance.

QA/testing prompts must support professional work without claiming execution, coverage, certification, or release approval.

## Workflow

Open a **Prompt proposal** issue for new categories or major additions. For a focused improvement, fork the repository, edit the relevant Markdown file, and open a pull request using the checklist.

Use a short commit message such as `Add supplier comparison prompt` or `Clarify evidence rule in bug report prompt`.
